# 模块任务: 人工审核模块

模块目标：向审核人员展示待审核内容，并把通过、拒绝、备注和重试动作回传给控制面。

## Checklist

- [ ] 定义审核对象数据结构，包含 `taskId`、仓库链接、推荐理由、风险提示、视频、封面、标题、简介、标签、字幕和配音。
- [ ] 定义 `POST /api/review/decision` 请求结构。
- [ ] 定义审核响应结构，包含最终状态。
- [ ] 实现审核详情查询接口或审核入口数据加载。
- [ ] 展示 GitHub 项目链接。
- [ ] 展示推荐理由。
- [ ] 展示风险提示。
- [ ] 展示视频成片预览。
- [ ] 展示封面图或封面文案。
- [ ] 展示标题。
- [ ] 展示简介。
- [ ] 展示标签。
- [ ] 展示字幕和配音检查入口。
- [ ] 实现审核通过动作。
- [ ] 实现审核拒绝动作。
- [ ] 实现审核备注填写。
- [ ] 定义允许的拒绝后动作枚举：`regenerate_title_description`、`regenerate_script`、`regenerate_tts`、`rerender_video`、`abandon_and_select_next`。
- [ ] 实现拒绝后动作选择或传递。
- [ ] 校验无效 `retryAction` 并返回错误。
- [ ] 审核通过时通知控制面更新为 `approved`。
- [ ] 审核拒绝时通知控制面更新为 `rejected`。
- [ ] 禁止审核通过前进入发布完成状态。
- [ ] 记录审核人、审核时间、决策和备注。
- [ ] 写入审核模块运行日志。
- [ ] 编写固定审核任务展示字段完整性测试。
- [ ] 编写 `approved` 决策回传测试。
- [ ] 编写 `rejected` 携带拒绝原因测试。
- [ ] 编写无效 `retryAction` 拒绝测试。
- [ ] 编写审核通过前不能发布测试。

## 完成定义

- [ ] 审核人员能看到发布前必须检查的全部对象。
- [ ] 通过和拒绝都能回传控制面。
- [ ] 人工审核是发布前强制节点。
